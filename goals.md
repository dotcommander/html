Interpreting “spec all” as: write implementation-ready specs for every shortlisted idea. No code changes.

**1. Cache Renderer Fingerprint**
Goal: Re-render cached HTML when embedded assets or renderer behavior changes, not only when the Markdown source mtime changes.

Invariants:
- Cache stays under `~/.config/html/cache/`.
- Cache key continues to collapse symlink/relative path variants.
- Existing `html -n/-f <file>` behavior stays compatible.

Scope:
- Add a renderer fingerprint derived from a constant schema version plus embedded `base.css`, `copy.js`, `theme.js`, and highlight CSS inputs.
- Store or compare that fingerprint near cache freshness, likely by embedding metadata in generated HTML or using a sidecar.
- Keep `--force` as unconditional rebuild.

Acceptance:
- Changing the render fingerprint makes `cache.Fresh` return false for an old cache.
- Existing mtime freshness tests still pass.
- Run `go test ./...` and `go vet ./...`.

**2. Accessibility And Mobile Polish**
Goal: Make rendered documents easier to use on mobile, keyboard, and assistive tech without changing Markdown semantics.

Invariants:
- Output remains one self-contained HTML file.
- No external fonts, icons, CSS, or JS.
- Keep the quiet reader-first style.

Scope:
- Add `:focus-visible` states for theme and copy buttons.
- Make copy controls discoverable on touch/coarse pointers.
- Prevent long inline code from causing page-width overflow.
- Add reduced-motion handling for transitions.
- Review table overflow behavior on narrow viewports.

Acceptance:
- A fixture with long inline code, wide tables, code blocks, task lists, and headings does not overflow incoherently on mobile width.
- Keyboard tab order reaches theme toggle and copy buttons visibly.
- Run `go test ./...`; visually inspect one rendered fixture.

**3. Render Fixture And Browser Smoke**
Goal: Catch regressions in the actual generated page, not just string fragments.

Invariants:
- Tests remain deterministic and local.
- No network dependency.
- Existing unit tests stay fast.

Scope:
- Add a representative Markdown fixture source in tests or generated in test code.
- Assert full-page essentials: theme script present before styles/body, copy script present, heading IDs generated, GFM tables/task lists render, CSS assets embedded.
- Optional second phase: browser smoke for theme toggle/copy button behavior if a repo-local browser tool is acceptable.

Acceptance:
- `go test ./...` fails if embedded asset order, GFM support, heading IDs, or copy/theme hooks disappear.
- If browser smoke is added, it can run locally without external services.

**4. Heading Tools / TOC**
Goal: Improve long-document navigation using the heading IDs already generated by Goldmark.

Invariants:
- Default output remains readable and uncluttered.
- TOC links must be same-page anchors.
- Generated HTML stays offline and self-contained.

Scope:
- Parse headings during render and collect level/text/id.
- Render a compact TOC only when document has enough headings, e.g. 4+ `h2/h3` entries, or gate behind future config.
- Add unobtrusive heading anchor links for direct copying.
- Keep styling restrained and mobile-safe.

Acceptance:
- Long docs get a working TOC with same-page links.
- Short docs do not gain unnecessary chrome.
- Heading text is escaped correctly.
- Tests cover nested headings and duplicate heading IDs.

**5. Optional Config File**
Goal: Add a single source of truth for user preferences without hardcoding new behavior in Go source.

Invariants:
- Missing config means current behavior.
- Invalid config returns clear CLI errors or ignores only explicitly safe optional fields.
- No environment-specific defaults beyond current macOS opener behavior.

Scope:
- Read `~/.config/html/config.json`.
- Start with small fields only: `open_command`, `max_width`, `default_theme`, maybe `toc`.
- Keep config loading at the CLI/action boundary, not inside render internals unless passed as options.
- Document the config shape in `CLAUDE.md` or a README if one is added.

Acceptance:
- Missing config path works exactly as today.
- Config can change open command or reader width without source edits.
- Tests cover missing, valid, and malformed config.

**6. Safe Raw-HTML Mode**
Goal: Allow safer rendering for untrusted or downloaded Markdown while preserving trusted local raw HTML behavior by default.

Invariants:
- Current default remains raw HTML passthrough unless explicitly changed.
- Safe mode must be visible in CLI/config, not hidden.
- Rendering still uses Goldmark/GFM.

Scope:
- Split renderer construction into unsafe/default and safe variants.
- Add `--safe` or config option to disable `goldmarkhtml.WithUnsafe()`.
- Add tests proving raw `<script>`/HTML is not passed through in safe mode and still passes in default mode.

Acceptance:
- `html --safe file.md` renders Markdown without raw HTML passthrough.
- Existing default render tests still pass.
- Run `go test ./...` and `go vet ./...`.

1. Browser fixture/smoke foundation.

4. Safe raw-HTML mode.
5. Heading tools/TOC.
6. Config file, once there are enough real knobs to justify it.
